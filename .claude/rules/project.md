# wireguard-go — Project Rules

This repo is **wireguard-go** (module `golang.zx2c4.com/wireguard`): a **userspace implementation
of the WireGuard VPN protocol in Go**. It builds the `wireguard-go` daemon (create a TUN interface,
speak the WireGuard wire protocol over UDP, configured via the cross-platform UAPI protocol) and is
also consumed as a Go module by the official WireGuard apps. It runs on Linux, macOS, Windows,
FreeBSD, OpenBSD, and mobile (Android/iOS) build variants.

> **This build extends upstream `wireguard-go`.** Alongside the standard UDP transport it provides a
> **WebSocket transport** in **server and client mode** (tunnelling the WireGuard wire protocol over
> WebSocket); it runs on **Linux, macOS, Windows, FreeBSD, OpenBSD**, and **Android** (usable as the
> Go backend of the official WireGuard Android app); and it is built and released through **GitHub
> Actions CI** and **goreleaser** as multi-platform binaries and a container image. Non-trivial work
> proceeds via the development pipeline per `development_pipeline.md`. The canonical docs MUST be
> kept current as changes land.

## Hard Project Invariants — ABSOLUTE RULES

- **WIRE PROTOCOL IS SACRED.** The daemon MUST remain interoperable with standard WireGuard
  (`Noise_IKpsk2_25519_ChaChaPoly_BLAKE2s`, message types 1–4, transport header layout). You MUST
  NOT alter on-the-wire formats, handshake semantics, or protocol constants (`device/constants.go`)
  unless the user EXPLICITLY asks.
- **PORTABILITY VIA INTERFACES.** New platforms or transports MUST be added behind the existing
  boundaries — `tun.Device`, `conn.Bind`, and the `ipc` UAPI transport — using build-tagged files.
  You MUST NOT push OS-specific logic into the `device` core.
- **CROSS-PLATFORM BUILDS MUST NOT BREAK.** A change MUST compile for ALL supported GOOS targets
  (linux, darwin, windows, freebsd, openbsd) and the mobile variants. When editing build-tagged
  files, you MUST keep every platform's file consistent.
- **UAPI IS A STABLE CONTRACT.** The `get=1`/`set=1` configuration protocol MUST stay compatible
  with `wg(8)` and the WireGuard apps.
- **NO EXTERNAL SERVICES.** There is NO database, broker, or third-party API. All I/O is the TUN
  device, UDP sockets, and the local UAPI control socket.
- **NO SECRETS IN LOGS.** Private keys, preshared keys, and key material MUST NEVER appear in logs
  or error messages.
- **CONCURRENCY IS REAL.** The data path is multi-goroutine with parallel crypto workers and
  per-peer sequential ordering. You MUST preserve ordering and lock discipline; you MUST run tests
  with `-race`.
- Keep it SIMPLE.

## Non-goals (MUST NOT build unless the user explicitly asks)

- No reimplementation of, or divergence from, the WireGuard wire protocol. No new config-file format
  (configuration stays UAPI-only). No database or persistent state. No metrics server, no web UI.
  No new fan-out/goroutine topology in the data path. No Kubernetes manifests in this repo.

## Standard Commands

The `Makefile` is the authoritative command surface:

- `make` / `make all` — regenerate `version.go` from `git describe` and build the `wireguard-go` binary.
- `make vet` — `go vet ./...`.
- `make lint` / `make lint-fix` — `golangci-lint run` / `golangci-lint run --fix`.
- `make test` — unit tests with the race detector (`go test -race ./...`).
- `make test-e2e` — full two-peer tunnel via `tests/netns.sh` (Linux + privileges).
- `make test-all` — unit + e2e.
- `make tidy` — `go mod tidy`.
- `make vulncheck` — `govulncheck ./...`.
- `make mermaid-check` — validate all Mermaid blocks under `docs/` per `development_pipeline.md` §9.
- `make snapshot` / `make release` — goreleaser build (`--snapshot`) / tagged release.
- `make install` / `make clean`.

**Quality gates**: `build`, `vet`, `lint`, `test-all` (race), `tidy` (with NO resulting
`go.mod`/`go.sum` diff), and `mermaid-check` (when Mermaid charts were touched) MUST ALL pass before
any work is considered DONE (per `development_pipeline.md` §2 and `go.md` §4).

## Testing — ABSOLUTE (project-specific)

- Tests MUST use the **standard library `testing` package** (this repo has NO `testify`; do NOT
  introduce it).
- Tests MUST NEVER hit real networks. Network I/O is faked with **in-repo harnesses**:
  - `conn/bindtest` — channel-backed `Bind` for two in-process devices.
  - `tun/tuntest` — in-memory TUN device.
  - `tun/netstack` — full userspace TCP/IP for loopback end-to-end checks.
- End-to-end tunnel behavior is exercised by `tests/netns.sh` (Linux network namespaces; needs
  Linux + privileges).
- **Testcontainers are NOT used** — there is no external service infrastructure. This is the
  documented exception to the testcontainers rule in `go.md`.
- The race detector (`-race`) is MANDATORY; data races are bugs, never warnings.

## Key Conventions

- **Interface-first portability** per `go.md`: OS/transport differences live behind `tun.Device`,
  `conn.Bind`, and the `ipc` UAPI transport, selected by build tags — NOT in the `device` core.
- **Explicit wiring**: the daemon is assembled in `main` via `device.NewDevice(tun, bind, logger)`.
  NO package-level globals for dependencies.
- **Per-OS files use build tags** (`//go:build` and `_linux`/`_darwin`/`_windows`/… suffixes); keep
  ALL platform variants in sync when changing shared behavior.
- **Ordering + locking** in the data path: parallel crypto workers, per-peer sequential
  send/receive. Preserve it.
- **Logging via `device.Logger`**, with interface/peer identifiers; NEVER key material.

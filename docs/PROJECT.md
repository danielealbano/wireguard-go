# wireguard-go — Project

`wireguard-go` is a **userspace implementation of the [WireGuard](https://www.wireguard.com/)
VPN protocol in Go**. It builds a single binary (`wireguard-go`) that creates a virtual network
interface, speaks the WireGuard wire protocol over UDP, and is configured through the standard
cross-platform WireGuard configuration protocol (UAPI) — the same one driven by
[`wg(8)`](https://git.zx2c4.com/wireguard-tools/about/src/man/wg.8). It is also consumed as a **Go
module** by the official WireGuard apps for Windows, macOS, iOS, and Android.

Go module path: `golang.zx2c4.com/wireguard`.

> **This repository is a fork used to extend upstream `wireguard-go`.** The upstream code is the
> canonical userspace WireGuard daemon and library. The extensions targeted here are captured in
> [Roadmap](#roadmap). All non-trivial feature work MUST proceed via the development pipeline
> (`.claude/rules/development_pipeline.md`), and these canonical docs MUST be kept current as
> decisions land.

---

## What It Does

- Creates/attaches a TUN interface and exchanges encrypted WireGuard datagrams with peers over UDP.
- Implements the WireGuard **Noise IKpsk2** handshake
  (`Noise_IKpsk2_25519_ChaChaPoly_BLAKE2s`) and the transport data protocol.
- Exposes the **cross-platform UAPI configuration protocol** over a per-interface control socket
  so tools such as `wg(8)` can set the private key, peers, endpoints, allowed IPs, and keepalives.
- Runs multi-platform: Linux, macOS (utun), Windows (wintun; test harness in-repo), FreeBSD,
  OpenBSD, plus mobile build variants (Android/iOS) consumed as a module.
- Ships an optional fully-userspace network stack (`tun/netstack`, backed by gVisor) that provides
  in-process TCP/UDP/ICMP without touching the host's networking — the foundation for embedding
  WireGuard in an application.

| `tun/tuntest/` | In-memory TUN test harness. |
| `ipc/` | UAPI transport: per-OS control socket (`/var/run/wireguard/<iface>.sock` on unix, named pipe on Windows) and error codes. |
| `conn/bindtest/` | In-memory `Bind` test harness (channel-backed, no real sockets). |
| `ratelimiter/` | Per-source-IP token-bucket limiter used to throttle handshake initiations under load (RFC-agnostic DoS mitigation). |
| `replay/` | Anti-replay sliding-window filter (RFC 6479). |
| `tai64n/` | TAI64N timestamp encoding for handshake initiation (anti-replay of handshakes). |

| `tests/netns.sh` | Linux network-namespace end-to-end tunnel test (two peers over loopback). |

## Configuration & Runtime Surfaces

`wireguard-go` takes **no config file**. It is configured entirely through the UAPI protocol after
startup, with a handful of environment variables controlling process behavior.

### Command line

```
wireguard-go [-f/--foreground] INTERFACE-NAME
wireguard-go --version
```

Without `-f`, the process daemonizes (forks into the background) on the unix platforms; the child
inherits the TUN and UAPI file descriptors. On Linux/FreeBSD/OpenBSD a banner is printed reminding
users the in-kernel WireGuard is preferable.

### Environment variables

| Variable | Effect |
|---|---|
| `LOG_LEVEL` | `verbose`/`debug`, `error`, or `silent`. Default: `error`. |
| `WG_TUN_FD` | Use an already-open TUN file descriptor instead of creating one. |
| `WG_UAPI_FD` | Use an already-open UAPI socket file descriptor. |
| `WG_PROCESS_FOREGROUND` | Set to `1` by the daemonizing parent for its child; forces foreground. |
| `WG_TUN_NAME_FILE` | On macOS/OpenBSD (kernel-chosen `utun`/`tun` names), the resolved interface name is written here. |
| `WG_TRANSPORT` | `udp` (default) or `ws` — selects the outer transport (UDP or WebSocket) at startup. |
| `WG_WS_ROLE` | `client` (default) or `server` — the WebSocket bind role. |
| `WG_WS_TLS_CERT` / `WG_WS_TLS_KEY` | Server `wss` certificate + key files. |
| `WG_WS_TLS_CA` / `WG_WS_TLS_SERVERNAME` / `WG_WS_TLS_INSECURE` | Client `wss` options (empty ⇒ system roots; `WG_WS_TLS_INSECURE=1` skips verification). |
| `WG_WS_BEARER` | Server-side expected pre-shared bearer (coarse gate, constant-time checked before upgrade). Never logged. |
| `WG_WS_PING_INTERVAL` | WebSocket ping/backstop interval (Go duration; sane default). |
| `WG_WS_MASK` | `1`/`true` masks client WebSocket frames (default off, unmasked — matches a default wstunnel server). When on, the peer wstunnel server MUST run `--websocket-mask-frame` (mask modes must match). |
| `WG_WS_TRUSTED_PROXIES` | Comma-separated CIDRs from which `X-Forwarded-For` is trusted (server behind an HTTP reverse proxy). |
| `WG_METRICS_LISTEN` | Prometheus `/metrics` listen address. Empty ⇒ metrics OFF. |

### UAPI configuration protocol

The device is configured/inspected with `get=1` / `set=1` operations over the control socket, per
the [cross-platform configuration protocol](https://www.wireguard.com/xplatform/#configuration-protocol).
Keys include the interface `private_key`, `listen_port`, `fwmark`, and per-peer `public_key`,
`endpoint`, `allowed_ip`, `persistent_keepalive_interval`, `preshared_key`, plus `remove`/`replace`
directives. `wg(8)` is the normal front-end.

The WebSocket transport adds these **additive** UAPI keys (accepted only when `WG_TRANSPORT=ws`):
the device key `ws_listen` (server listen URL) and the per-peer keys `ws_mode` (`standard`|`wstunnel`),
`ws_target` (real WireGuard `host:port` for `wstunnel` mode), and `ws_bearer` (write-only client bearer,
never echoed by `get=1` or logged). Peer `endpoint` values may be `ws(s)://host:port/path` URLs.

### Control socket / named pipe

- **Unix:** `/var/run/wireguard/<iface>.sock` (a UNIX domain socket; `socketDirectory` is
  overridable via linker flags). Deleting the socket shuts the daemon down.
- **Windows:** a named pipe (`ipc/namedpipe`).

## Platforms

| Platform | Status | Notes |
|---|---|---|
| Linux | Supported | Prefer the in-kernel module for production. GSO/GRO UDP offload and route (netlink) listening supported. |
| macOS | Supported | `utun` driver; interface must be `utun[0-9]+` or `utun`. No sticky sockets; no fwmark (Darwin limitation). |
| Windows | Supported (as a module) | Uses Wintun. `main_windows.go` is a debugging harness; the real client is `wireguard-windows`. |
| FreeBSD | Supported | No sticky sockets. Fwmark → `SO_USER_COOKIE`. |
| OpenBSD | Supported | No sticky sockets. Fwmark → `SO_RTABLE`. `tun[0-9]+`/`tun` naming rule like macOS. |
| Android / iOS | Supported (as a module) | Dedicated queue constants and mobile roaming quirks (`DisableSomeRoamingForBrokenMobileSemantics`). |

## Build & Commands

The **Makefile is the authoritative command surface**. Current targets:

- `make` / `make all` — regenerate `version.go` from `git describe` and build the `wireguard-go` binary.
- `make test` — `go test ./...`.
- `make install` — install to `$(DESTDIR)$(PREFIX)/bin`.
- `make clean` — remove the built binary.

Direct commands used for the quality gates (see `go.md` §4):

- Build: `go build ./...`
- Vet: `go vet ./...`
- Lint: `golangci-lint run`
- Tests (race): `go test -race ./...`
- Tidy: `go mod tidy`
- Vulnerabilities: `govulncheck ./...`

> The Makefile does not yet expose `lint`/`vet`/`race`/release targets — extending it, plus adding
> CI and release automation, is [Roadmap](#roadmap) work.

## Testing

- Tests use the **standard library `testing` package only** (no `testify`).
- Network I/O is faked with **in-repo harnesses**, never live networks:
  - `conn/bindtest` — channel-backed `Bind` for two in-process devices.
  - `tun/tuntest` — in-memory TUN device.
  - `tun/netstack` — full userspace TCP/IP for loopback end-to-end checks.
- `tests/netns.sh` runs a **two-peer end-to-end tunnel** across Linux network namespaces
  (Linux + privileges required).
- **Testcontainers are not used** — there is no external service infrastructure. This is the
  documented exception to the testcontainers rule in `go.md`.
- The race detector (`-race`) is mandatory.

## Roadmap

Delivered in this fork (plan `docs/plans/1_websocket_transport_*.md`):

1. **WebSocket transport** — a `conn.Bind`-level transport tunnelling the WireGuard wire protocol over
   `ws(s)://` in both **server** and **client** modes, with `standard` and `wstunnel` dialects,
   reconnect + OS-path-monitor roaming, egress pinning, an optional bearer gate, trusted-proxy `XFF`,
   and an optional Prometheus metrics listener.
2. **macOS/Android support** — the client bind builds for the mobile targets; a per-dial
   `VpnService.protect` callback and the exported `BindUpdate` bump are the only cross-language
   contracts (the app/libwg-go layers are external; see `docs/ANDROID_INTEGRATION.md`).
3. **CI, release, and packaging** — GitHub Actions quality gates, **goreleaser** `v2.17.1`
   multi-platform binaries, and a multi-arch container image published to
   `ghcr.io/danielealbano/wireguard-go`.

See `docs/ARCHITECTURE.md` for how these map onto the existing `conn`/`tun`/`device` boundaries.
